# วิธีการทำห้องสมุดดิจิทัล (How to Build a Digital Library)

> งานค้นคว้าว่าด้วยขั้นตอน องค์ประกอบ มาตรฐาน และเทคโนโลยีในการสร้าง "ห้องสมุดดิจิทัล"
> ตั้งแต่แนวคิดจนถึงระบบที่ใช้งานได้จริง

---

## 1. ห้องสมุดดิจิทัลคืออะไร

**ห้องสมุดดิจิทัล (Digital Library)** คือระบบที่ **จัดเก็บ จัดระเบียบ สงวนรักษา และให้บริการ**
ทรัพยากรความรู้ในรูปแบบ **ดิจิทัล** (ไฟล์เอกสาร รูปภาพ เสียง วิดีโอ ข้อมูลวิจัย ฯลฯ)
ผ่านเครือข่ายคอมพิวเตอร์ โดยยังคงหน้าที่หลักของห้องสมุดไว้ครบ —
เพียงเปลี่ยน "ชั้นหนังสือกายภาพ" เป็น "พื้นที่จัดเก็บข้อมูล" และ "การเดินไปหยิบ"
เป็น "การเข้าถึงผ่านเครือข่าย"

> เชื่อมโยง: หน้าที่หลัก 4 ด้านของห้องสมุดดูได้ใน [how-library-works.md](how-library-works.md)
> ห้องสมุดดิจิทัลคือการนำหน้าที่เหล่านั้นมา implement ด้วยซอฟต์แวร์

### ความต่างจาก "ห้องสมุดที่มีของดิจิทัล"

| | ห้องสมุดทั่วไป (มี e-book บ้าง) | ห้องสมุดดิจิทัลเต็มรูปแบบ |
|---|---|---|
| แกนหลักของคอลเลกชัน | กายภาพเป็นหลัก | ดิจิทัลทั้งหมด |
| การเข้าถึง | ต้องมาที่อาคาร | ที่ไหน เมื่อไรก็ได้ |
| สำเนา | จำกัดตามจำนวนเล่ม | ผู้ใช้หลายคนพร้อมกัน (ขึ้นกับสัญญาอนุญาต) |
| การค้นหา | OPAC (ค้น metadata) | full-text search ในเนื้อหาได้ |

## 2. องค์ประกอบหลักของระบบ (Architecture)

ห้องสมุดดิจิทัลประกอบด้วยชั้นการทำงาน (layers) ที่ชัดเจน:

```
┌─────────────────────────────────────────────────┐
│  ชั้นผู้ใช้ (Presentation)                          │
│  เว็บพอร์ทัล / แอป / ช่องค้นหา / หน้าอ่าน (viewer)   │
├─────────────────────────────────────────────────┤
│  ชั้นบริการ (Services)                             │
│  ค้นหา (Search) · ยืนยันตัวตน (Auth) · สิทธิ์ (DRM) │
│  เก็บสถิติ · API · เก็บเกี่ยว metadata (OAI-PMH)     │
├─────────────────────────────────────────────────┤
│  ชั้น metadata & ดัชนี (Catalog/Index)             │
│  ฐานข้อมูล metadata + search engine (ดัชนี)         │
├─────────────────────────────────────────────────┤
│  ชั้นจัดเก็บวัตถุดิจิทัล (Repository/Storage)        │
│  ไฟล์จริง (PDF, รูป, วิดีโอ) + สำเนาสำรอง            │
├─────────────────────────────────────────────────┤
│  ชั้นสงวนรักษา (Preservation)                       │
│  สำรองข้อมูล · ตรวจสอบความครบถ้วน · ย้ายฟอร์แมต      │
└─────────────────────────────────────────────────┘
```

**หลักการสำคัญ:** แยก **"วัตถุดิจิทัล (object)"** ออกจาก **"ข้อมูลอธิบาย (metadata)"**
และแยก **"ดัชนีค้นหา (index)"** ออกอีกชั้น — เหมือนห้องสมุดจริงที่แยก "ตัวหนังสือบนชั้น"
ออกจาก "บัตรรายการ/OPAC"

## 3. ขั้นตอนการสร้างห้องสมุดดิจิทัล (Step by Step)

### ขั้นที่ 1: วางแผนและกำหนดขอบเขต (Planning)
- กำหนด **กลุ่มผู้ใช้** และ **วัตถุประสงค์** (วิชาการ? จดหมายเหตุ? สาธารณะ?)
- กำหนด **ขอบเขตคอลเลกชัน** (Collection Development Policy) — จะเก็บอะไร ไม่เก็บอะไร
- ประเมิน **งบประมาณ ลิขสิทธิ์ และทรัพยากรบุคคล**

### ขั้นที่ 2: ได้มาซึ่งเนื้อหาดิจิทัล (Content Acquisition)
มี 2 ทางหลัก:
1. **การแปลงเป็นดิจิทัล (Digitization)** — สแกนหนังสือ/เอกสารกายภาพ
   - สแกนความละเอียดสูง (มาตรฐานเก็บถาวรมักใช้ TIFF, ใช้งานจริงเป็น PDF/JPEG)
   - ทำ **OCR (Optical Character Recognition)** เพื่อให้ค้นหาข้อความในภาพได้
2. **เนื้อหาที่เกิดในรูปดิจิทัลอยู่แล้ว (Born-digital)** — e-book, ไฟล์วิจัย, ฐานข้อมูลบอกรับ

### ขั้นที่ 3: สร้าง Metadata (Cataloging)
ลงข้อมูลอธิบายวัตถุแต่ละชิ้นตามมาตรฐาน (ดูหัวข้อ 4) เพื่อให้ค้นหาและจัดการได้

### ขั้นที่ 4: เลือกและติดตั้งระบบ (Platform)
เลือกซอฟต์แวร์ repository (ดูหัวข้อ 5) ติดตั้ง ปรับแต่ง และนำเข้าข้อมูล

### ขั้นที่ 5: ทำดัชนีและระบบค้นหา (Indexing & Search)
ป้อน metadata + ข้อความ full-text เข้า search engine สร้าง **inverted index**
เพื่อให้ค้นได้รวดเร็ว

### ขั้นที่ 6: ควบคุมการเข้าถึงและสิทธิ์ (Access & Rights)
ตั้งระบบยืนยันตัวตน, สิทธิ์การเข้าถึง, และการจัดการลิขสิทธิ์ (ดูหัวข้อ 6)

### ขั้นที่ 7: วางแผนสงวนรักษาดิจิทัล (Digital Preservation)
สำรองข้อมูล ตรวจสอบความครบถ้วน และวางแผนย้ายฟอร์แมต (ดูหัวข้อ 7)

### ขั้นที่ 8: เปิดให้บริการและบำรุงรักษา (Launch & Maintain)
เปิดใช้ เก็บสถิติการใช้ รับ feedback ปรับปรุงต่อเนื่อง

## 4. มาตรฐาน Metadata ที่ใช้

Metadata คือหัวใจที่ทำให้ค้นหาและแลกเปลี่ยนข้อมูลได้ มาตรฐานสำคัญ:

| มาตรฐาน | ใช้ทำอะไร |
|---------|-----------|
| **Dublin Core** | ชุด metadata พื้นฐาน 15 ฟิลด์ (Title, Creator, Subject, Date ฯลฯ) นิยมที่สุดในงานดิจิทัล |
| **MARC / MARCXML** | มาตรฐานบรรณานุกรมห้องสมุดดั้งเดิม (เชื่อมกับระบบห้องสมุดเดิมได้) |
| **MODS** | Metadata บรรณานุกรมแบบ XML ละเอียดกว่า Dublin Core |
| **METS** | ห่อหุ้มโครงสร้างของวัตถุดิจิทัล (มัดไฟล์+metadata เป็นชุดเดียว) |
| **PREMIS** | Metadata เพื่อการสงวนรักษา (บันทึกประวัติไฟล์ การแปลงฟอร์แมต) |
| **OAI-PMH** | โพรโทคอล **เก็บเกี่ยว metadata** ข้ามคลังกัน (ทำให้ค้นรวมหลายห้องสมุดได้) |
| **IIIF** | มาตรฐานแสดงและแชร์ภาพความละเอียดสูง (ใช้กับเอกสารหายาก/ต้นฉบับ) |

> เทียบกับห้องสมุดจริง: Dublin Core/MARC ก็คือ "บัตรรายการ" เวอร์ชันดิจิทัล
> ส่วน OAI-PMH คือ "สหบรรณานุกรม (Union Catalog)" แบบอัตโนมัติ

## 5. ซอฟต์แวร์/แพลตฟอร์ม (Repository Software)

ไม่จำเป็นต้องเขียนเองทั้งหมด มีซอฟต์แวร์โอเพนซอร์สที่ใช้กันแพร่หลาย:

| ซอฟต์แวร์ | เหมาะกับ | จุดเด่น |
|-----------|----------|---------|
| **DSpace** | คลังสารสนเทศสถาบัน (Institutional Repository) | นิยมในมหาวิทยาลัย รองรับ OAI-PMH |
| **Omeka** | นิทรรศการ/คอลเลกชันดิจิทัล จดหมายเหตุ | ติดตั้งง่าย สวยงาม เหมาะกับงานจัดแสดง |
| **Greenstone** | ห้องสมุดดิจิทัลทั่วไป (UNESCO สนับสนุน) | ใช้ออฟไลน์ได้ รองรับหลายภาษา |
| **Fedora Commons** | คลังขนาดใหญ่ที่ต้องการความยืดหยุ่นสูง | สถาปัตยกรรมยืดหยุ่น เน้น preservation |
| **Invenio** | คลังข้อมูลวิจัย (พัฒนาโดย CERN) | รองรับชุดข้อมูลขนาดใหญ่ |
| **Koha** | ระบบห้องสมุดอัตโนมัติ (ILS) ที่ผูกกับดิจิทัลได้ | เป็น ILS เต็มรูปแบบโอเพนซอร์ส |

**องค์ประกอบเทคนิคเบื้องหลัง** (หากสร้างเอง):
- **ฐานข้อมูล:** PostgreSQL/MySQL เก็บ metadata
- **Search engine:** Elasticsearch / Apache Solr ทำ full-text index
- **Object storage:** ระบบไฟล์/S3 เก็บไฟล์จริง
- **Web framework + viewer:** สำหรับแสดงผลและอ่านเอกสาร

## 6. การเข้าถึง สิทธิ์ และลิขสิทธิ์ (Access & Rights)

ปัญหาใหญ่ของห้องสมุดดิจิทัลคือ **ลิขสิทธิ์** — ทำสำเนาดิจิทัลง่าย แต่กฎหมายคุ้มครอง

- **ยืนยันตัวตน (Authentication):** ล็อกอินสมาชิก, SSO, IP-based (เข้าจากในเครือข่ายสถาบัน)
- **การจัดการสิทธิ์ดิจิทัล (DRM):** จำกัดการคัดลอก/พิมพ์/ยืมตามเวลา
- **โมเดลการเข้าถึง:**
  - **Open Access** — เปิดฟรี (เหมาะกับเนื้อหาที่หมดลิขสิทธิ์/เจ้าของอนุญาต)
  - **บอกรับ (Subscription)** — เข้าถึงตามสิทธิ์ที่จ่าย
  - **Controlled Digital Lending (CDL)** — ยืมดิจิทัลแบบ "1 สำเนา = 1 คนต่อครั้ง" เลียนแบบหนังสือจริง
- **สัญญาอนุญาตแบบเปิด:** Creative Commons (CC) สำหรับเนื้อหาที่ต้องการแบ่งปัน
- **ตัวระบุถาวร (Persistent Identifier):** ใช้ **DOI / Handle / ARK** เพื่อให้ลิงก์ไม่เสียแม้ย้ายระบบ

## 7. การสงวนรักษาดิจิทัล (Digital Preservation)

ความเข้าใจผิดที่อันตรายที่สุด: "ดิจิทัลแล้วอยู่ได้ตลอดไป" — **ไม่จริง**
ไฟล์เสียหายได้ (bit rot) และฟอร์แมตล้าสมัยจนเปิดไม่ได้

วิธีแก้ที่ใช้กัน:
1. **สำรองหลายชุดหลายที่ (LOCKSS — Lots Of Copies Keep Stuff Safe)**
2. **ตรวจสอบความครบถ้วน (Fixity / Checksum)** — เก็บค่า hash (MD5/SHA) คอยตรวจว่าไฟล์ไม่เพี้ยน
3. **ย้ายฟอร์แมต (Format Migration)** — แปลงไปฟอร์แมตใหม่ก่อนของเก่าตาย
4. **ใช้ฟอร์แมตเปิดมาตรฐาน (Open Formats)** — เช่น PDF/A, TIFF ที่มีโอกาสอ่านได้นาน
5. **บันทึก metadata การสงวนรักษา (PREMIS)** — ติดตามประวัติทุกการเปลี่ยนแปลง

> เทียบกับห้องสมุดจริง: นี่คือ "การควบคุมอุณหภูมิ/ความชื้น" และ "การเข้าเล่มใหม่"
> เวอร์ชันดิจิทัล — ต้องดูแลตลอดอายุ ไม่ใช่ทำครั้งเดียวจบ

---

## 8. การเทียบเคียงกับวิทยาการคอมพิวเตอร์

ห้องสมุดดิจิทัลคือ "ห้องสมุดจริง" ที่ถูก implement ด้วยแนวคิดระบบเต็มรูปแบบ:

| แนวคิดห้องสมุดดิจิทัล | แนวคิดวิทยาการคอมพิวเตอร์ |
|----------------------|---------------------------|
| แยก object / metadata / index | **Separation of concerns / 3-tier architecture** |
| Full-text search + inverted index | **Search engine indexing** |
| OAI-PMH เก็บเกี่ยวข้ามคลัง | **API / Data federation / ETL** |
| Checksum (Fixity) | **Hashing / Integrity check** |
| LOCKSS สำรองหลายชุด | **Replication / Redundancy** |
| Format migration | **Schema/Data migration** |
| Persistent Identifier (DOI/Handle) | **Stable URI / Indirection layer** |
| Controlled Digital Lending | **Concurrency control / Licensing token** |
| Object storage แยกจาก DB | **Blob storage vs metadata DB** |

## 9. สรุป: เช็กลิสต์สร้างห้องสมุดดิจิทัล

- [ ] กำหนดผู้ใช้ วัตถุประสงค์ และขอบเขตคอลเลกชัน
- [ ] วางแผนลิขสิทธิ์และงบประมาณ
- [ ] ได้มาซึ่งเนื้อหา (สแกน + OCR หรือ born-digital)
- [ ] เลือกมาตรฐาน metadata (เริ่มที่ Dublin Core)
- [ ] เลือก/ติดตั้งแพลตฟอร์ม (เช่น DSpace, Omeka)
- [ ] ตั้งระบบค้นหา full-text (Solr/Elasticsearch)
- [ ] กำหนดการเข้าถึง สิทธิ์ และ persistent identifier
- [ ] วางแผนสงวนรักษา (สำรอง + checksum + migration)
- [ ] เปิดบริการ เก็บสถิติ และบำรุงรักษาต่อเนื่อง

**แก่นสำคัญ:** ห้องสมุดดิจิทัลไม่ใช่แค่ "เอาไฟล์ไปวางบนเว็บ" แต่คือการนำหลักการห้องสมุด —
**คัดเลือก จัดระเบียบ ค้นหาได้ เข้าถึงได้ และรักษาไว้ได้นาน** — มาสร้างใหม่ด้วยเทคโนโลยี
โดยมี "การสงวนรักษาระยะยาว" เป็นโจทย์ที่ยากและสำคัญที่สุด
