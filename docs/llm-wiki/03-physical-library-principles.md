# หลักการห้องสมุดกายภาพที่ยืมมา (Physical Library Principles) — ชั้น 3 (ครึ่งแรก)

> เอกสารนี้ทำหน้าที่ **รวบรวม "กล่องเครื่องมือ" ของศาสตร์ห้องสมุด (library science)**
> ที่เราจะหยิบยืมมาใช้บริหาร **คอลเลกชันของหนังสือ** (หลาย llm-wiki-book) —
> ได้แก่ การลงรายการ/metadata, การจัดหมวดหมู่, citation & provenance, FRBR,
> การหมุนเวียน/นโยบายคอลเลกชัน และการสงวนรักษา

> **ขอบเขตที่ชัดเจน:** เอกสารนี้ **"สกัดหลักการ" (extract) เท่านั้น** —
> ยังไม่ลงมือประกอบเข้ากับ llm-wiki-library การ "ประยุกต์ใช้จริง (apply)"
> เป็นความรับผิดชอบของ [04-llm-wiki-library.md](04-llm-wiki-library.md)

> อ้างอิงโมเดลกลาง: [00-overview.md](00-overview.md) ·
> ฐานความรู้ห้องสมุด: [../how-library-works.md](../how-library-works.md) ·
> เวอร์ชันดิจิทัล: [../how-to-build-digital-library.md](../how-to-build-digital-library.md)

## 1. ทำไมต้องยืมหลักการห้องสมุด

ในโมเดล 3 ชั้นของชุดเอกสารนี้ (ดู [00-overview.md](00-overview.md)) —
**ชั้น 2 = หนังสือหนึ่งเล่ม (llm-wiki-book)** และ **ชั้น 3 = ห้องสมุด (llm-wiki-library)**
เมื่อเรามีหนังสือ "หลายเล่ม" แทนที่จะมีเล่มเดียว ปัญหาใหม่ก็โผล่มาทันที —
ปัญหาเดียวกับที่ห้องสมุดกายภาพแก้มาหลายร้อยปี:

> **ทำอย่างไรให้ค้นเจอ "เล่มที่ต้องการ" จาก "เล่มนับร้อยนับพัน" ได้เร็ว ถูกต้อง
> เชื่อถือได้ และไม่ปนกัน?** (ดูบทตั้งโจทย์ใน [../how-library-works.md](../how-library-works.md#1-ห้องสมุดคืออะไรในเชิงระบบ))

ศาสตร์ห้องสมุดให้คำตอบที่ผ่านการพิสูจน์แล้ว เราจึงไม่ต้องประดิษฐ์ใหม่ —
แค่ "ยืม" หลักการมา แล้ว map เข้ากับสิ่งที่คอลเลกชัน llm-wiki-book ต้องการ

## 2. ทบทวน 4 หน้าที่หลัก แล้ว map เข้าคอลเลกชัน llm-wiki-book

ห้องสมุดทำงานด้วย 4 หน้าที่หลักที่หมุนเป็นวงจร (ดู [../how-library-works.md](../how-library-works.md#1-ห้องสมุดคืออะไรในเชิงระบบ))
เราถอดมาเป็น "สิ่งที่คอลเลกชันของเล่มต้องมี":

| หน้าที่ห้องสมุด | ความหมายเดิม | map → คอลเลกชัน llm-wiki-book |
|----------------|--------------|------------------------------|
| **เก็บ** (Acquisition/Store) | คัดเลือก/รับของเข้าคลัง | ยอมรับเล่มใหม่เข้าห้องสมุดตามนโยบายคอลเลกชัน + เก็บ `raw/`+`wiki/` ของแต่ละเล่ม |
| **จัดระเบียบ** (Cataloging & Classification) | ลงรายการ + ให้เลขหมู่ | สร้าง "ระเบียนของเล่ม" (metadata) + จัดหมวดตามหัวข้อ ให้แต่ละเล่มมี "ที่อยู่" ที่ค้นเจอ |
| **ค้นหา** (Reference/Discovery) | OPAC ค้นจากดัชนี | catalog เหนือเล่ม: เลือกเล่ม/ค้นข้ามเล่ม โดยคงขอบเขตของแต่ละเล่มไว้ |
| **หมุนเวียน** (Circulation/Access) | ยืม-คืน คุมการใช้ร่วม | สิทธิ์เข้าถึง + เวอร์ชัน/ฉบับใดของเล่มที่ "ใช้ได้ตอนนี้" + การอ้างอิงข้ามเล่ม |

> สังเกตว่า "หมุนเวียน" ในบริบทดิจิทัลไม่ใช่การกันเล่มซ้ำ (mutex) แบบกายภาพอีกต่อไป
> แต่กลายเป็นเรื่อง **สิทธิ์เข้าถึง + การชี้ไปยังเวอร์ชัน/ฉบับที่ถูกต้อง** (ดูหัวข้อ 8)

## 3. การลงรายการและ metadata (Cataloging & Metadata)

หัวใจของ "การจัดระเบียบ" คือการสร้าง **ระเบียน (record)** ที่แยกออกจากตัวของจริง —
เหมือนบัตรรายการ/OPAC ที่แยกจากตัวหนังสือบนชั้น
(ดู [../how-library-works.md](../how-library-works.md#3-การวิเคราะห์หมวดหมู่-cataloging--classification--หัวใจของห้องสมุด))

### 3.1 มาตรฐานที่ยืมมา

ใช้มาตรฐานเดียวกับที่งานดิจิทัลใช้ (ดูตารางเต็มใน
[../how-to-build-digital-library.md](../how-to-build-digital-library.md#4-มาตรฐาน-metadata-ที่ใช้)):

- **Dublin Core** — ชุด metadata พื้นฐาน 15 ฟิลด์ (Title, Creator, Subject, Date, …)
  เบาและเริ่มง่าย เหมาะเป็น "ระเบียนแกน" ของแต่ละเล่ม
- **MARC / MARCXML** — มาตรฐานบรรณานุกรมห้องสมุดดั้งเดิม ละเอียด แลกเปลี่ยนข้ามระบบได้
  (copy cataloging — ลงทีเดียว ที่อื่นดึงไปใช้ต่อ)
- **MODS / METS / PREMIS** — ละเอียดขึ้น, ห่อโครงสร้างวัตถุ, และเก็บประวัติการสงวนรักษา

### 3.2 "ระเบียนของหนังสือ" (catalog record) ควรจับอะไรบ้าง

ถ้า llm-wiki-book หนึ่งเล่มคือ "หนังสือ" ระเบียนของมันควรบันทึก (อย่างน้อย):

| ฟิลด์ (เทียบ Dublin Core) | สำหรับ llm-wiki-book หมายถึง |
|---------------------------|------------------------------|
| Title | ชื่อหัวข้อ/ขอบเขตของเล่ม |
| Creator / Contributor | ใคร/โมเดล/ทีมที่ดูแลการ synthesis |
| Subject | หัวเรื่อง/หมวด (โยงกับ classification หัวข้อ 4) |
| Date | วันที่สร้าง/อัปเดต wiki ล่าสุด |
| Identifier | ตัวระบุถาวรของเล่ม (โยง persistent ID หัวข้อ 5) |
| Source / Relation | `raw/` ที่เป็นที่มา + ลิงก์ไปเล่มอื่นที่อ้างถึง |
| Description | สรุปขอบเขต + สถานะ lint (ดู [01-book-pipeline.md](01-book-pipeline.md)) |
| Version / Edition | เวอร์ชัน/ฉบับของเล่ม (โยง FRBR หัวข้อ 6) |

> หลักการที่ยืม: **แยก "ข้อมูลอธิบาย (metadata)" ออกจาก "ตัวเนื้อหา (object)"**
> ตามที่ย้ำใน [../how-to-build-digital-library.md](../how-to-build-digital-library.md#2-องค์ประกอบหลักของระบบ-architecture)

## 4. การจัดหมวดหมู่และหัวเรื่อง (Classification & Subject Access)

การลงรายการบอกว่า "เล่มนี้คืออะไร" — การจัดหมวดบอกว่า "เล่มนี้อยู่ที่ไหน/เกี่ยวกับเรื่องอะไร"
ทำให้ค้นและจัดวางตามหัวข้อได้
(พื้นฐานดูใน [../how-library-works.md](../how-library-works.md#3-ระบบจัดหมวดหมู่-หัวใจของการค้นหา))

### 4.1 ระบบจัดหมวดหมู่ (Classification Schemes)

| ระบบ | ลักษณะ | เหมาะกับ |
|------|--------|----------|
| **DDC** (Dewey Decimal) | ทศนิยม 000–900 แบ่งย่อยได้ลึก (เช่น `005.13` = ภาษาโปรแกรม) | คอลเลกชันทั่วไป/กลาง |
| **LCC** (Library of Congress) | ใช้ตัวอักษร A–Z นำหน้า 21 หมวดหลัก แบ่งกว้างกว่า | คอลเลกชันขนาดใหญ่/วิจัย |

ทั้งสองให้คุณสมบัติเดียวกันที่เราต้องการ: **locality** — เล่มหัวข้อใกล้กันอยู่ใกล้กัน
ทำให้เดินดู (browse) ตามหมวดได้ และ **เลขเรียก (call number)** ที่เรียงลำดับได้
(sorted) + แทรกเล่มใหม่ได้โดยไม่ต้องจัดใหม่ทั้งหมด

```
   005.133        ◄── เลขหมู่ (หัวข้อ)        = "เกี่ยวกับเรื่องอะไร"
   K18l           ◄── เลขผู้แต่ง (Cutter)     = "ของใคร/เรียงยังไง"
   2026           ◄── ปี/เวอร์ชัน            = "ฉบับไหน"
```

### 4.2 คำศัพท์ควบคุม (Controlled Vocabulary) และการควบคุมรายการหลักฐาน (Authority Control)

ปัญหาคลาสสิก: ถ้าปล่อยให้ใส่หัวเรื่อง/ชื่ออิสระ จะเกิด "คำเดียวกันสะกดต่าง / คนเดียวกันหลายชื่อ"
ทำให้ค้นไม่เจอหรือกระจัดกระจาย วิธีแก้คือ:

- **Controlled Vocabulary** — บัญชีคำที่อนุญาตให้ใช้เป็นหัวเรื่อง (เช่น LCSH —
  Library of Congress Subject Headings) เพื่อให้ "หัวข้อเดียว = คำเดียว"
- **Authority Control** — กำหนด "รูปแบบที่เป็นทางการ (authorized form)" ของชื่อ/หัวเรื่อง
  หนึ่งรายการ แล้วผูก "รูปแบบอื่น (variant/see-also)" เข้าหากัน
  → เหมือน **canonical key + alias mapping** ในฐานข้อมูล

> หลักการที่ยืม: ตรึง "คำ" และ "ชื่อ" ให้เป็นมาตรฐานก่อน แล้วค้นหาจึงจะ **รวมศูนย์ (collocation)**
> ได้จริง — เล่มที่เรื่องเดียวกันจะมารวมกันแม้ผู้สร้างจะตั้งคำต่างกัน

## 5. citation & provenance (กระดูกสันหลังของความน่าเชื่อถือ)

ในโมเดลกลาง **citation คือหัวใจของชั้น 3** (ดู [00-overview.md](00-overview.md#5-การรวมร่าง-llm-wiki-library-ชั้น-3--ครึ่งหลัง))
ศาสตร์ห้องสมุดมีประเพณีเรื่องการอ้างอิงและการพิสูจน์ที่มา (provenance) ที่ยืมมาได้ตรง ๆ:

### 5.1 การอ้างอิงบรรณานุกรม (Bibliographic Reference)

ทุกข้อความที่ยืนยันความรู้ ต้องชี้กลับไปยัง "ที่มา" ได้ — เหมือนเชิงอรรถ/บรรณานุกรมท้ายเล่ม
ในบริบทเรานี่คือ **การผูกหน้า wiki กลับไปยัง `raw/`** (ในเล่ม) และ
**การอ้างถึงหน้า/ข้อความในอีกเล่ม** (ข้ามเล่ม)

### 5.2 ตัวระบุถาวร (Persistent Identifiers — PID)

ปัญหา "ลิงก์เน่า (link rot)" ทำให้การอ้างอิงพังเมื่อย้ายระบบ — แก้ด้วย PID
(ดู [../how-to-build-digital-library.md](../how-to-build-digital-library.md#6-การเข้าถึง-สิทธิ์-และลิขสิทธิ์-access--rights)):

| PID | ลักษณะ |
|-----|--------|
| **DOI** (Digital Object Identifier) | ID ถาวรสำหรับสิ่งพิมพ์/ชุดข้อมูล มี resolver กลาง |
| **Handle** | ระบบ identifier ใต้ DOI; ชี้ตัววัตถุแบบ persistent |
| **ARK** (Archival Resource Key) | PID สำหรับงานจดหมายเหตุ/วัตถุดิจิทัลระยะยาว |

> หลักการที่ยืม: **ชื่อ (identifier) ต้องคงที่ แม้ที่อยู่ (location) เปลี่ยน** —
> เป็นชั้น indirection ระหว่าง "การอ้างอิง" กับ "ตำแหน่งจริง" → citation ไม่พังเมื่อ refactor

### 5.3 provenance = ความเชื่อถือได้

provenance คือ "ประวัติว่าของชิ้นนี้มาจากไหน ผ่านอะไรมาบ้าง" — ในห้องสมุด/จดหมายเหตุถือเป็น
หลักฐานความแท้ (authenticity) เก็บได้ด้วย PREMIS (ดูหัวข้อสงวนรักษา)
สำหรับคอลเลกชันเรา provenance = สายโซ่ `raw → ingest → synthesis` ที่ตามรอยย้อนได้

## 6. โมเดล FRBR (Work / Expression / Manifestation / Item)

เมื่อ "หนังสือเล่มหนึ่ง" มีหลายเวอร์ชัน/หลายฉบับ/หลายสำเนา การพูดว่า "หนังสือเล่มนี้" เริ่มกำกวม
**FRBR** (Functional Requirements for Bibliographic Records) แยกแนวคิดออกเป็น 4 ระดับ (กลุ่ม 1):

```
WORK            "ผลงาน" เชิงนามธรรม (idea/เนื้อหาแก่น)
  │  realized through
  ▼
EXPRESSION      "การแสดงออก" เฉพาะ (เวอร์ชัน/ฉบับแปล/ฉบับปรับปรุงเนื้อหา)
  │  embodied in
  ▼
MANIFESTATION   "รูปลักษณ์ที่ตีพิมพ์" (รูปแบบ/ชุดเผยแพร่ของ expression นั้น)
  │  exemplified by
  ▼
ITEM            "ตัวเล่มจริง" หนึ่งสำเนา (copy เดียวที่จับต้องได้)
```

map เข้ากับ **versioning ของ llm-wiki-book**:

| ระดับ FRBR | ในห้องสมุดจริง | สำหรับ llm-wiki-book |
|-----------|----------------|----------------------|
| **Work** | "แฮมเล็ต" ในฐานะผลงาน | เล่ม = หัวข้อ/ขอบเขตเชิงแนวคิด (เอกลักษณ์ไม่ขึ้นกับเวอร์ชัน) |
| **Expression** | ฉบับแก้ครั้งที่ 2, ฉบับแปล | สถานะ wiki หลัง synthesis รอบหนึ่ง = หนึ่งเวอร์ชันเนื้อหา |
| **Manifestation** | การพิมพ์ครั้งของสำนักพิมพ์หนึ่ง | snapshot/ชุดเผยแพร่ของเวอร์ชันนั้น (เช่น export/แท็ก release) |
| **Item** | เล่มที่อยู่บนชั้นจริง | สำเนาที่ถูกจัดเก็บ/ติดตั้งจริง ณ ที่หนึ่ง |

> ทำไมสำคัญ: เวลา query/citation เราต้องตอบให้ได้ว่ากำลังอ้างถึง **Work** (หัวข้อโดยรวม)
> หรือ **Expression** (เวอร์ชันเนื้อหาเจาะจง) — เพราะเล่มเดียวกันที่ผ่าน synthesis หลายรอบ
> จะมีหลาย expression การอ้างอิงที่ดีต้องตรึงระดับให้ชัด มิฉะนั้น citation จะกำกวม
> รายละเอียดการประยุกต์อยู่ใน [04-llm-wiki-library.md](04-llm-wiki-library.md)

## 7. นโยบายพัฒนาคอลเลกชัน (Collection Development Policy)

ก่อน "เก็บ" ต้องตอบให้ได้ว่า **จะรับอะไรเข้าคอลเลกชัน และไม่รับอะไร**
นี่คือขั้น Acquisition ที่มีนโยบายกำกับ (ดู [../how-library-works.md](../how-library-works.md#1-การจัดหา-acquisition)):

- **เกณฑ์รับเข้า (selection):** ขอบเขต/คุณภาพ/ความเกี่ยวข้องกับผู้ใช้/ความซ้ำซ้อนกับเล่มที่มี
- **ความสมดุลของคอลเลกชัน:** ครอบคลุมหัวข้ออย่างมีสัดส่วน ไม่กระจุก
- **การคัดออก (Weeding/Deselection):** คัดเล่มที่ล้าสมัย/ไม่มีคนใช้/ซ้ำซ้อนออก เพื่อคงคุณภาพ

> สำหรับ llm-wiki-library: นโยบายนี้ตอบว่า "llm-wiki-book เล่มไหน *มีสิทธิ์* เข้าห้องสมุด"
> และ "เล่ม/เวอร์ชันไหนควรปลดระวาง" — เกณฑ์อาจรวมสถานะ lint (เช่น เล่มที่ขัดแย้งภายในเยอะ)

## 8. การหมุนเวียนและการเข้าถึง (Circulation & Access)

ในห้องสมุดกายภาพ การหมุนเวียนคือยืม-คืน คุมไม่ให้ใช้เล่มเดียวกันชนกัน
ในบริบทดิจิทัล/คอลเลกชันเรา หลักที่ยืมมาคือ
(ดู [../how-to-build-digital-library.md](../how-to-build-digital-library.md#6-การเข้าถึง-สิทธิ์-และลิขสิทธิ์-access--rights)):

- **สิทธิ์เข้าถึง (Access model):** เปิด (open) / จำกัด — ใครอ่าน/ค้นเล่มไหนได้
- **ชี้ไปยังฉบับที่ใช้ได้ตอนนี้:** OPAC บอก "ว่าง/ถูกยืม" → ของเรา catalog บอกว่า
  "เวอร์ชัน/expression ใดเป็นฉบับปัจจุบันที่ควรอ่าน/อ้างถึง"
- **การค้นข้ามเล่ม (cross-collection discovery):** ดัชนีเหนือเล่มให้ค้นได้ทั้งคอลเลกชัน
  โดยยังคงขอบเขตแต่ละเล่ม — เทียบ OAI-PMH/สหบรรณานุกรม
  (ดู [../how-to-build-digital-library.md](../how-to-build-digital-library.md#4-มาตรฐาน-metadata-ที่ใช้))

## 9. การสงวนรักษา (Preservation)

คอลเลกชันต้องอยู่ได้นาน ทั้งตัวเนื้อหาและ provenance หลักการเรื่องนี้มีอยู่ครบแล้วใน
เอกสารดิจิทัล — **ยืมมาตรงทั้งหมด ไม่ทำซ้ำ**:

> ดูรายละเอียด: [../how-to-build-digital-library.md §7](../how-to-build-digital-library.md#7-การสงวนรักษาดิจิทัล-digital-preservation)
> — LOCKSS (สำเนาหลายชุด), Fixity/Checksum, Format Migration, Open Formats, PREMIS

แก่นที่ต้อง carry forward: **"ดิจิทัลไม่ได้อยู่ได้เองตลอดไป"** — `raw/` ที่ immutable
และเวอร์ชันของ wiki ต้องมีกลไกตรวจความครบถ้วน + สำรอง เพื่อให้ citation ย้อนรอยได้จริงในระยะยาว

## 10. ตาราง: หลักการห้องสมุด → สิ่งที่คอลเลกชัน llm-wiki-book ต้องมี

| หลักการห้องสมุด (ยืมมา) | สิ่งที่คอลเลกชัน llm-wiki-book ต้องมี |
|--------------------------|---------------------------------------|
| Cataloging + Dublin Core/MARC | ระเบียน metadata ต่อเล่ม (title, creator, subject, identifier, version) |
| Classification (DDC/LCC) + call number | หมวดหัวข้อ + "ที่อยู่" ของเล่ม ที่เรียงลำดับและแทรกเล่มใหม่ได้ |
| Controlled vocabulary + Authority control | หัวเรื่อง/ชื่อแบบ canonical + alias → ค้นแล้วรวมศูนย์ |
| Bibliographic reference | ทุกข้อความผูกกลับ `raw/` (ในเล่ม) + อ้างข้ามเล่มได้ |
| Persistent Identifier (DOI/Handle/ARK) | ID ถาวรต่อเล่ม/เวอร์ชัน → citation ไม่พังเมื่อย้าย/refactor |
| Provenance (+PREMIS) | สายโซ่ `raw → ingest → synthesis` ที่ตามรอยย้อนได้ |
| FRBR (Work→Expression→Manifestation→Item) | แยกระดับ "หัวข้อเล่ม / เวอร์ชันเนื้อหา / snapshot / สำเนา" ให้ชัด |
| Collection Development Policy | เกณฑ์รับเข้า + คัดออก ว่าเล่ม/เวอร์ชันไหนอยู่ในห้องสมุด |
| Circulation / Access | สิทธิ์เข้าถึง + ชี้ "ฉบับปัจจุบัน" + ค้นข้ามเล่ม |
| Preservation (LOCKSS/Fixity/Migration) | สำรอง + checksum + แผนย้ายฟอร์แมต เพื่ออายุยืน |

## 11. ขอบเขต: เอกสารนี้ "สกัด" ไม่ "ประกอบ"

ย้ำอีกครั้งเพื่อกันสับสนกับเอกสาร 04:

| เอกสารนี้ (03) ทำ | เอกสาร 04 ทำ |
|--------------------|---------------|
| **สกัด (extract)** หลักการห้องสมุดล้วน ๆ มาเป็นกล่องเครื่องมือ | **ประกอบ (apply)** หลักการเหล่านี้เข้ากับ llm-wiki + citation เป็น llm-wiki-library |
| ตอบว่า "ห้องสมุดมีเครื่องมืออะไรให้ยืมบ้าง" | ตอบว่า "เอาเครื่องมือมาเรียงร้อยเป็นระบบจริงอย่างไร" |

> การลงมือออกแบบ schema, รูปแบบ citation ข้ามเล่ม, catalog เหนือเล่ม ฯลฯ
> อยู่ใน [04-llm-wiki-library.md](04-llm-wiki-library.md) ทั้งหมด

## 12. เช็กลิสต์หลักการห้องสมุดที่ต้อง carry forward

หลักการที่เอกสาร 04 ต้องหยิบไปใช้ต่อ:

- [ ] **ระเบียน metadata ต่อเล่ม** — เริ่มที่ Dublin Core, เชื่อม MARC ได้
- [ ] **จัดหมวดตามหัวข้อ** — เลือกแนวทาง classification + call-number-like address
- [ ] **Authority control + controlled vocabulary** — canonical ชื่อ/หัวเรื่อง + alias
- [ ] **citation ผูกที่มา** — ในเล่ม (`raw/`) และข้ามเล่ม (bibliographic link)
- [ ] **Persistent Identifier** — ID ถาวรต่อเล่ม/เวอร์ชัน กัน link rot
- [ ] **Provenance** — เก็บสายโซ่ที่มาแบบตามรอยย้อนได้ (โยง PREMIS)
- [ ] **FRBR-aware versioning** — แยก Work / Expression / Manifestation / Item ให้ชัด
- [ ] **Collection Development Policy** — เกณฑ์รับเข้า + คัดออก
- [ ] **Access model** — สิทธิ์เข้าถึง + ชี้ฉบับปัจจุบัน + ค้นข้ามเล่ม
- [ ] **Preservation** — สำรอง + Fixity + Format migration (ดูเอกสารดิจิทัล)

> ถัดไป: [04-llm-wiki-library.md](04-llm-wiki-library.md) — นำเช็กลิสต์นี้ไปประกอบเป็น
> ห้องสมุดของ llm-wiki-book ที่มี citation เป็นหัวใจ
