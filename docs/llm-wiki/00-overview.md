# LLM-Wiki Library — ภาพรวมและโมเดลแนวคิด (Canonical Overview)

> ชุดงานวิจัยว่าด้วยการสร้าง **ห้องสมุดของหนังสือที่เป็น LLM-Wiki** โดย:
> (1) ผลิตหนังสือแต่ละเล่มด้วยไปป์ไลน์ **ingest → synthesis → lint → query**
> แบบที่ได้แรงบันดาลใจจาก *Karpathy LLM Wiki* (2) มองผลลัพธ์นั้นเป็น **หนังสือ 1 เล่ม
> (llm-wiki-book)** และ (3) นำหลักการ **ห้องสมุดกายภาพ (physical library)** มารวมกับ
> หลักการ **llm-wiki** เพื่อเก็บหนังสือเข้าสู่ **ห้องสมุด (llm-wiki-library)** แบบ **citation**

> เอกสารนี้เป็น "โมเดลกลาง (canonical model)" ที่เอกสารลูกทุกชิ้นในชุดนี้ต้องยึดตาม
> เพื่อให้ศัพท์และสถาปัตยกรรมตรงกัน

---

## 0. หมายเหตุการปรับวัตถุประสงค์ (สำคัญ)

เอกสารรุ่นก่อนในรีโปนี้ ([../llm-wiki-library.md](../llm-wiki-library.md),
[../llm-wiki-adoption-workflow.md](../llm-wiki-adoption-workflow.md)) ตั้งกรอบว่า
"หนังสือ = ต้นฉบับนิ่ง + LLM ที่ทำ **RAG ดึงข้อความตอนถาม**" ซึ่ง **ยังไม่ตรงเป้าหมาย**

ชุดเอกสารนี้ปรับให้ตรงตามแนวคิด *Karpathy LLM Wiki*:

| ประเด็น | กรอบเดิม (RAG-centric) | **กรอบที่ถูกต้อง (Wiki-compile-centric)** |
|---------|------------------------|-------------------------------------------|
| หนังสือคืออะไร | ต้นฉบับ + ดัชนีเวกเตอร์ | **wiki ที่ถูกสังเคราะห์และดูแลโดย LLM** (raw → wiki) |
| ความรู้เกิดเมื่อไร | ตอน query (stateless) | **สะสมล่วงหน้า (stateful, compounding)** |
| RAG | เป็นแกน | **เป็นทางเลือก** — query อ่านจากหน้า wiki ที่สังเคราะห์ไว้แล้ว |
| บทบาท LLM | ดึง+ตอบ | **คอมไพล์ raw เป็น wiki + ดูแล (ingest/synthesis/lint)** |

> เปรียบเทียบของ Karpathy: `raw/` = ซอร์สโค้ด, LLM = คอมไพเลอร์, `wiki/` = ไฟล์ที่รันได้,
> `lint` = เทสต์, `query` = รันไทม์

## 1. โมเดล 3 ชั้นซ้อน (Nested Model)

```
╔══════════════════════════════════════════════════════════════╗
║  ชั้น 3 · LLM-WIKI-LIBRARY  (ห้องสมุด)                          ║
║  หลัก physical-library + llm-wiki → เก็บหลายเล่มแบบ citation     ║
║  catalog · classification · cross-book citation · preservation ║
║                                                                ║
║   ┌────────────────────────────────────────────────────────┐ ║
║   │ ชั้น 2 · LLM-WIKI-BOOK  (หนังสือ 1 เล่ม)                  │ ║
║   │ = ผลลัพธ์ของไปป์ไลน์ = หนึ่ง Karpathy-wiki                │ ║
║   │   raw/ (immutable)  ·  wiki/ (สังเคราะห์)  ·  schema      │ ║
║   │                                                          │ ║
║   │   ┌──────────────────────────────────────────────────┐ │ ║
║   │   │ ชั้น 1 · BOOK PIPELINE  (โรงงานผลิตเล่ม)            │ │ ║
║   │   │ raw หลายแหล่ง                                      │ │ ║
║   │   │   → ingest → synthesis → lint → query              │ │ ║
║   │   └──────────────────────────────────────────────────┘ │ ║
║   └────────────────────────────────────────────────────────┘ ║
╚══════════════════════════════════════════════════════════════╝
```

- **ชั้น 1 (Pipeline)** = *วิธีทำ* หนังสือหนึ่งเล่มจากความรู้ดิบหลายแหล่ง
- **ชั้น 2 (Book)** = *หน่วย* หนึ่งเล่ม (เปรียบได้กับหนังสือบนชั้น)
- **ชั้น 3 (Library)** = *คอลเลกชัน* ของหลายเล่ม + ระเบียบแบบห้องสมุด + citation

## 2. ไปป์ไลน์ผลิตหนังสือ (ชั้น 1)

```
แหล่งความรู้ดิบหลายที่ (papers, โน้ต, โค้ด, บทสนทนา, เว็บ)
        │
        ▼
[ingest]    นำเข้า + ย่อย source ทีละชิ้น (เก็บ raw แบบ immutable)
        │
        ▼
[synthesis] LLM เขียน/อัปเดต "หน้า wiki" ที่เชื่อมโยงกัน
            (สรุป, entity, concept, index, log) — นี่คือ "การคอมไพล์"
        │
        ▼
[lint]      ตรวจสุขภาพ wiki: ข้อขัดแย้ง · ข้อมูลล้าสมัย · หน้ากำพร้า (orphan)
            · ลิงก์ข้ามที่ขาด · ช่องว่างความรู้
        │
        ▼
[query]     ถาม-ตอบจากหน้า wiki ที่สังเคราะห์ไว้ คำตอบดี ๆ ถูก "filed back"
            เป็นหน้าใหม่ → ความรู้ compound
```

> รายละเอียดเต็มอยู่ใน [01-book-pipeline.md](01-book-pipeline.md)

## 3. หนังสือหนึ่งเล่ม = llm-wiki-book (ชั้น 2)

หนึ่งเล่มคือหนึ่ง Karpathy-wiki ที่มีขอบเขตหัวข้อชัดเจน ประกอบด้วย 3 ส่วน:

| ส่วน | บทบาท | เทียบหนังสือจริง |
|------|-------|------------------|
| `raw/` | แหล่งดิบ **immutable** (ความจริง/ที่มา) | เอกสารอ้างอิงท้ายเล่ม / ภาคผนวก |
| `wiki/` | หน้าที่ LLM สังเคราะห์ เชื่อมโยงกัน | เนื้อหาเล่มที่อ่านได้ |
| `schema` | กติกาว่า LLM ต้องประพฤติ/จัดหน้าอย่างไร | แนวทางบรรณาธิการ (style guide) |

> รายละเอียดเต็มอยู่ใน [02-llm-wiki-book.md](02-llm-wiki-book.md)

## 4. หลักการห้องสมุดกายภาพที่นำมาใช้ (ชั้น 3 — ครึ่งแรก)

นำ "ศาสตร์ห้องสมุด" มาทำให้ *คอลเลกชันของเล่ม* ค้นเจอ จัดระเบียบ และเชื่อถือได้:
catalog/metadata (Dublin Core/MARC), classification (DDC/LCC), citation & provenance,
circulation/access, preservation, FRBR (work/expression/manifestation/item)

> รายละเอียดเต็มอยู่ใน [03-physical-library-principles.md](03-physical-library-principles.md)

## 5. การรวมร่าง: llm-wiki-library (ชั้น 3 — ครึ่งหลัง)

เอาชั้น 2 (หลายเล่ม) มาวางในระเบียบของชั้น "ห้องสมุด" โดยมี **citation เป็นหัวใจ**:
- citation **ภายในเล่ม**: ทุกหน้า wiki ผูกกลับ `raw/` (ที่มา)
- citation **ข้ามเล่ม**: เล่ม A อ้างถึงหน้า/ข้อความในเล่ม B ได้ (bibliographic link)
- catalog เหนือเล่ม: เลือกเล่ม/จัดหมวด/ค้นข้ามเล่ม โดยคงขอบเขตของแต่ละเล่ม

> รายละเอียดเต็มอยู่ใน [04-llm-wiki-library.md](04-llm-wiki-library.md)

## 6. อภิธานศัพท์ใหม่ (Glossary)

| คำ | ความหมายในชุดนี้ |
|----|------------------|
| **raw** | แหล่งความรู้ดิบ เก็บแบบ immutable เป็น "ความจริง/ที่มา" |
| **ingest** | นำเข้าและย่อย source ใหม่เข้าสู่กระบวนการ |
| **synthesis** | LLM สังเคราะห์/อัปเดตหน้า wiki ที่เชื่อมโยงกัน ("คอมไพล์") |
| **lint** | ตรวจสุขภาพ wiki (ขัดแย้ง/ล้าสมัย/กำพร้า/ลิงก์ขาด) |
| **query** | ถาม-ตอบจาก wiki แล้ว file คำตอบที่ดีกลับเป็นหน้าใหม่ |
| **llm-wiki-book** | หนังสือ 1 เล่ม = หนึ่ง Karpathy-wiki (raw + wiki + schema) |
| **llm-wiki-library** | คอลเลกชันของ llm-wiki-book + หลักห้องสมุด + citation |
| **citation** | การผูกคำตอบ/ข้อความกลับไปยังที่มา (ในเล่ม และข้ามเล่ม) |
