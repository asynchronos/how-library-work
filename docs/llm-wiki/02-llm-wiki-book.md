# LLM-Wiki-Book — หนังสือหนึ่งเล่มในฐานะหน่วย (ชั้น 2)

> เอกสารนี้ว่าด้วย **"หนังสือหนึ่งเล่ม (llm-wiki-book)"** — การมอง Karpathy-style LLM wiki
> **หนึ่งตัว** เป็น **หนังสือหนึ่งเล่ม** ที่เป็น *หน่วย* (unit) สมบูรณ์ในตัวเอง: ข้างในมีอะไร,
> อะไรทำให้มันมี **อัตลักษณ์ (identity)** และ **ขอบเขต (boundary)**, และมันมีพฤติกรรม
> อย่างไรในฐานะ "วัตถุ" ที่ห้องสมุดจะหยิบไปจัดเก็บบนชั้นได้ในภายหลัง

> เอกสารนี้ยึดโมเดลกลางใน [00-overview.md](00-overview.md) (โมเดล 3 ชั้น) และรับผิดชอบ
> **เฉพาะชั้น 2** เท่านั้น
> - *วิธีสร้าง* เล่ม (ingest → synthesis → lint → query) เป็นของ [01-book-pipeline.md](01-book-pipeline.md) — ที่นี่จะ **อ้างถึง ไม่อธิบายซ้ำลึก**
> - *การจัดเก็บหลายเล่มเป็นคอลเลกชัน/ห้องสมุด* เป็นของ [03-physical-library-principles.md](03-physical-library-principles.md) และ [04-llm-wiki-library.md](04-llm-wiki-library.md)
>

## 1. หนึ่งเล่มคืออะไร (นิยามการทำงาน)

> **llm-wiki-book** = Karpathy-wiki **หนึ่งตัว** ที่มีขอบเขตหัวข้อชัดเจน ประกอบด้วย
> `raw/` (ที่มา immutable) + `wiki/` (หน้าที่สังเคราะห์และเชื่อมโยงกัน) + `schema`
> (กติกาบรรณาธิการ) — เป็น **ฐานความรู้ markdown ที่อ่านได้ในตัวเอง (self-contained)
> และเชื่อมโยงภายในกันเอง (interlinked)** ที่ผู้ใช้ "สนทนา" ด้วยได้

จุดสำคัญที่แยกจากกรอบเดิม (ดู §0 ของ [00-overview.md](00-overview.md)): ความรู้ใน "เล่ม"
ถูก **สังเคราะห์ล่วงหน้า (pre-compiled)** ลงเป็นหน้า wiki ไม่ใช่ค้นสด ๆ จากต้นฉบับตอนถาม
เล่มจึงเป็น **วัตถุที่มีสถานะ (stateful object)** ความรู้ **สะสมทบต้น (compounding)** ไม่ใช่
ค้นใหม่ทุกครั้ง

เปรียบเทียบของ Karpathy ที่ยึดทั้งชุด: `raw/` = ซอร์สโค้ด, LLM = คอมไพเลอร์,
`wiki/` = ไฟล์ที่รันได้, `lint` = เทสต์, `query` = รันไทม์ ⇒ **หนึ่งเล่ม = หนึ่งโปรเจกต์ที่คอมไพล์แล้ว**

## 2. กายวิภาคของหนึ่งเล่ม (Anatomy)

หนึ่งเล่มมีสามส่วนหลัก สองส่วนเป็นไดเรกทอรี หนึ่งส่วนเป็นไฟล์กติกา:

| ส่วน | สถานะ | บทบาท | เทียบหนังสือจริง |
|------|-------|-------|------------------|
| `raw/` | **immutable** (อ่านอย่างเดียว) | ที่มา/ความจริง — papers, โน้ต, โค้ด, บทสนทนา, ภาพ, ข้อมูล | เอกสารอ้างอิงท้ายเล่ม / ภาคผนวก / หลักฐาน |
| `wiki/` | **regenerable** (สร้างใหม่ได้) | หน้าที่ LLM สังเคราะห์ เชื่อมโยงกันด้วย wikilink | เนื้อหาเล่มที่อ่านได้จริง |
| `schema` (เช่น `CLAUDE.md` / `AGENTS.md`) | กติกา | บอก LLM ว่าโครงสร้างเล่มเป็นอย่างไร ใช้ระเบียบ/เวิร์กโฟลว์ใด | แนวทางบรรณาธิการ (style guide) |

ภายใน `wiki/` มีหน้าได้หลายชนิด (ตามแนวทาง Karpathy):

| ชนิดหน้า | เนื้อหา |
|----------|---------|
| **entity page** | คน/องค์กร/สิ่งเฉพาะ หนึ่งหน้าต่อหนึ่ง entity |
| **concept page** | แนวคิด/ธีม/โดเมนเชิงอธิบาย |
| **summary page** | สรุป source ที่ ingest เข้ามาทีละชิ้น |
| **comparison page** | วิเคราะห์เทียบข้าม source |
| `index.md` | สารบัญ: ลิงก์ทุกหน้า + สรุปบรรทัดเดียว + เมตาดาตา จัดตามหมวด |
| `log.md` | บันทึกต่อท้าย (append-only) ตามลำดับเวลา เช่น `## [2026-04-02] ingest | <ชื่อ source>` |

### แผนผัง "ภายในหนึ่งเล่ม"

```
┌──────────────────── llm-wiki-book (หนึ่งเล่ม) ────────────────────┐
│                                                                   │
│  schema  ──►  CLAUDE.md / AGENTS.md   (กติกาบรรณาธิการ)            │
│               ความรู้: โครงสร้าง · ระเบียบ · เวิร์กโฟลว์            │
│                                                                   │
│  ┌────────── raw/  (IMMUTABLE = ที่มา) ──────────┐                 │
│  │  paper-01.pdf   notes.md   code/   chat.json  │  ◄── อ่านอย่างเดียว
│  └───────────────────┬───────────────────────────┘                │
│                      │  synthesis (คอมไพล์) — ดู 01-book-pipeline   │
│                      ▼                                             │
│  ┌────────── wiki/  (REGENERABLE = เนื้อเล่ม) ──────────┐          │
│  │  index.md ──┬─► entity/karpathy.md ──[[link]]──┐     │          │
│  │             ├─► concept/compounding.md ◄───────┘     │          │
│  │             └─► comparison/rag-vs-wiki.md            │          │
│  │  log.md  (append-only)                              │          │
│  │  ทุกข้ออ้าง ─────cite────► raw/<file>#<loc>          │          │
│  └─────────────────────────────────────────────────────┘          │
│                                                                   │
│   query  ◄── ผู้ใช้ "สนทนากับเล่ม": ถามจาก wiki/ ที่สังเคราะห์ไว้   │
└───────────────────────────────────────────────────────────────────┘
```

> เส้นทาง `raw/ → synthesis → wiki/` คือ *งานของไปป์ไลน์* — รายละเอียดอยู่ใน
> [01-book-pipeline.md](01-book-pipeline.md) ที่นี่สนใจแค่ **ผลลัพธ์ที่เป็นเล่ม**

## 3. ขอบเขตและสโคปของเล่ม (Boundary / Scope)

> **กฎหัวใจ: หนึ่งเล่ม = หนึ่งหัวข้อ/โดเมน (one book = one topic/domain)**

ขอบเขตของเล่มถูกกำหนดโดย **"ชุด `raw/` ที่ผูกกับหัวข้อเดียว"** บวกกับ **schema ที่ระบุ
สโคป** ไม่ใช่ทุกอย่างในโลกควรอยู่ในเล่มเดียว เหตุผลที่ต้อง scope ให้แคบและคม:

| ถ้า scope แคบ (one topic/เล่ม) | ถ้าทำเป็น wiki ยักษ์ใบเดียว |
|--------------------------------|------------------------------|
| หน้าเชื่อมโยงกันแน่น ความหมายไม่ปนข้ามโดเมน | ลิงก์ข้ามโดเมนสับสน entity ชื่อซ้ำชนกัน |
| lint ทำงานได้แม่น (orphan/contradiction ในวงแคบ) | สัญญาณรบกวนสูง ตรวจสุขภาพยาก |
| query ให้คำตอบคมเพราะบริบทคุมได้ | คำตอบเจือจาง บริบทเฟ้อ |
| หยิบทั้งเล่มไปจัดหมวด/อ้างอิงข้ามเล่มได้ (ชั้น 3) | เป็นก้อนเดียว แยกชั้น/อ้างอิงไม่ได้ |
| version/regenerate เล่มเดียวได้เร็ว | ทุกการแก้กระทบทั้งระบบ |

> สโคปคือสิ่งที่ทำให้เล่ม "หยิบไปวางบนชั้นห้องสมุดได้" — ขอบเขตคมเท่ากับ **เป็นหน่วย
> (unit) ที่จัดหมวดและอ้างอิงข้ามเล่มได้** ซึ่งเป็นเงื่อนไขที่ชั้น 3 ต้องการ
> (ดู [04-llm-wiki-library.md](04-llm-wiki-library.md))

## 4. อัตลักษณ์และการทำเวอร์ชัน (Identity & Versioning)

เล่มหนึ่ง **ไม่นิ่ง**: เมื่อ `raw/` โตขึ้น (ingest source ใหม่) `wiki/` ก็ถูกสังเคราะห์เพิ่ม/
ปรับ เล่มจึง **เติบโตเป็น edition ใหม่** ได้เรื่อย ๆ หลักคิดเรื่องเวอร์ชัน:

- **raw คือ source of truth ที่ immutable** — ไม่แก้ของเดิม มีแต่ **เพิ่ม** source ใหม่
  (append) การ immutable นี้คือการออกแบบโดยตั้งใจ: ทำให้ **regenerate `wiki/` ใหม่
  ทั้งหมดจาก `raw/` ได้เสมอ**
- **wiki regenerable** — ถือ `wiki/` เป็น *artifact ที่คอมไพล์ได้* ไม่ใช่ของล้ำค่าที่หายแล้วหายเลย
  ถ้าระเบียบ/schema เปลี่ยน ก็คอมไพล์ใหม่ได้
- **identity ของเล่ม** = (หัวข้อ/สโคป) + (ชุด `raw/` ณ จุดเวลาหนึ่ง) + (schema)
  สองอย่างหลังเปลี่ยน ⇒ ได้ "edition" ใหม่ของ *เล่มเดิม* ไม่ใช่เล่มใหม่
- **provenance**: ทุกข้ออ้างใน `wiki/` ต้อง **สืบกลับไป `raw/` ได้** — ถ้าหน้า wiki พูดอะไร
  ที่ไม่มี raw รองรับ ถือเป็น defect ที่ lint ควรจับ

```
raw/  (immutable, append-only)        wiki/ (regenerable artifact)
 v1: {S1, S2}            ──compile──►   edition 1
 v2: {S1, S2, S3}        ──compile──►   edition 2   (raw เดิมไม่ถูกแก้)
 v3: {S1..S4}            ──compile──►   edition 3
        ▲ source of truth คงที่           ▲ สร้างใหม่ได้เสมอจาก raw
```

> เปรียบกับโมเดลห้องสมุด FRBR: หัวข้อเล่มคือ *work*, แต่ละ edition คือ *expression*,
> สแนปช็อต `wiki/` ที่คอมไพล์ ณ เวลาหนึ่งคือ *manifestation* — เชื่อมเข้าชั้น 3 ใน
> [03-physical-library-principles.md](03-physical-library-principles.md)

## 5. การอ้างอิงภายในเล่ม (Internal Citation)

ภายในหนึ่งเล่มมีลิงก์สองชนิด:

1. **wiki ↔ wiki** — เชื่อมหน้าด้วย wikilink `[[Title]]` สร้าง backlink ให้รู้ว่าหน้าใด
   อ้างถึงหน้าใด เป็นโครงข่ายความรู้ภายในเล่ม
2. **wiki → raw** — *citation ที่เป็นหัวใจ*: ทุกข้ออ้างในหน้า wiki ผูกกลับไฟล์ใน `raw/`
   พร้อมตำแหน่ง เช่น

```markdown
แนวคิด compounding knowledge สะสมทบต้นเมื่อคำตอบถูก file กลับเป็นหน้าใหม่
[^1]

[^1]: raw/karpathy-llm-wiki.gist.md, ส่วน "query" (ingested 2026-04-02)
```

> citation ภายในเล่มนี้คือ **รากฐานของ citation ข้ามเล่ม** ในชั้น 3 — เล่ม B จะอ้างหน้า
> ในเล่ม A ได้ก็ต่อเมื่อหน้านั้นมี provenance ชัดในตัวเอง (ดู [04-llm-wiki-library.md](04-llm-wiki-library.md))

## 6. เล่มในฐานะ "ส่วนต่อประสาน" (Book as Interface)

หนังสือเล่มนี้ไม่ได้มีไว้ "เปิดอ่านเอง" อย่างเดียว — มันเป็น **อินเทอร์เฟซที่สนทนาได้**:
ผู้ใช้ตั้งคำถาม → LLM อ่าน `index.md` → ดึงหน้าที่เกี่ยว → สังเคราะห์คำตอบ **พร้อม citation
กลับ raw** → คำตอบที่ดีถูก **file back** เป็นหน้า wiki ใหม่ ทำให้เล่ม "ฉลาดขึ้น" ทุกครั้งที่ถูกถาม

จุดสำคัญสำหรับชั้น 2: การ query อ่านจาก `wiki/` ที่สังเคราะห์ไว้แล้ว **ไม่ใช่** ค้นสดจาก
`raw/` (นั่นคือความต่างจาก RAG) — กลไก query เต็ม ๆ อยู่ใน [01-book-pipeline.md](01-book-pipeline.md)

## 7. เทียบกับวัตถุความรู้แบบอื่น (Comparison)

| มิติ | หนังสือกระดาษ | หน้า web wiki เดียว | RAG corpus | **llm-wiki-book** |
|------|----------------|---------------------|------------|--------------------|
| หน่วย | เล่มนิ่ง | หน้า/ไซต์ที่คนแก้ | กองเอกสาร + ดัชนีเวกเตอร์ | **เล่ม = raw + wiki + schema** |
| ความรู้เกิดเมื่อ | เขียนครั้งเดียว | คนค่อย ๆ แก้ | ตอน query (stateless) | **สังเคราะห์ล่วงหน้า สะสมทบต้น** |
| ที่มา/provenance | บรรณานุกรมท้ายเล่ม | อ้างบ้างไม่อ้างบ้าง | chunk ที่ retrieve | **ทุกข้ออ้าง → `raw/` ตามรอยได้** |
| ผู้ดูแล | มนุษย์ + สำนักพิมพ์ | มนุษย์หลายคน | ไม่มี (ค้นอย่างเดียว) | **LLM คอมไพล์/lint ตาม schema** |
| ถามตอบได้ไหม | ไม่ได้ | ไม่ได้ (อ่านเอง) | ได้ แต่ค้นใหม่ทุกครั้ง | **ได้ จาก wiki ที่ pre-compiled** |
| สร้างใหม่ได้ไหม | ต้องพิมพ์ใหม่ | แก้ทีละหน้า | re-index | **regenerate `wiki/` จาก `raw/`** |
| ขอบเขต | ชัด (ปก) | คลุมเครือ ลิงก์ออกนอก | ทั้งกอง | **ชัด: หนึ่งหัวข้อ/โดเมน** |

## 8. เช็กลิสต์: เล่มที่ "ฟอร์มดี" (Well-formed llm-wiki-book)

- [ ] มี `raw/`, `wiki/`, และ `schema` (เช่น `CLAUDE.md`/`AGENTS.md`) ครบสามส่วน
- [ ] `raw/` ถูกปฏิบัติแบบ **immutable** (append-only ไม่แก้ของเดิม)
- [ ] `wiki/` **regenerate ได้ทั้งหมดจาก `raw/`** (ไม่มีความรู้ลอยที่ไม่มี raw รองรับ)
- [ ] มี `index.md` ครอบทุกหน้า + สรุปบรรทัดเดียว และ `log.md` แบบ append-only
- [ ] ทุกข้ออ้างใน `wiki/` มี **citation กลับ `raw/`** (provenance สืบรอยได้)
- [ ] หน้า wiki เชื่อมโยงกันด้วย wikilink ไม่มีหน้ากำพร้า (orphan) ค้าง(lint ผ่าน)
- [ ] **ขอบเขตหนึ่งหัวข้อ/โดเมนชัด** — ไม่ปนหลายโดเมนในเล่มเดียว
- [ ] schema ระบุสโคป ระเบียบหน้า และเวิร์กโฟลว์ของเล่มอย่างชัดเจน
- [ ] query อ่านจาก `wiki/` ที่สังเคราะห์ไว้ (ไม่ค้นสดจาก raw) และ file คำตอบดี ๆ กลับได้
- [ ] เล่ม **หยิบไปจัดหมวด/อ้างอิงข้ามเล่มได้** ในชั้น 3 (มี identity + boundary คม)
